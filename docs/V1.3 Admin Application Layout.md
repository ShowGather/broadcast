# ShowGather V1.3 Admin Application Layout

## Governing principle

The Admin is one production application with a stable outer shell and three
distinct operating modes:

```text
Prepare -> Rehearse -> Run
```

It is not a collection of technical forms on separate routes. The canonical
command, outbox, timed transport, snapshot and execution-session systems stay
behind the operator-facing workflow.

## Stable shell

Every route uses a persistent top bar, production context, API/stream status,
mode navigation, active workspace, and secondary diagnostics entry. Production
selection remains available except while an active live session makes changing
production unsafe.

```text
ShowGather | Production | status | API | Stream
------------------------------------------------
Prepare / Rehearse / Run | Productions | Settings
------------------------------------------------
Active workspace
------------------------------------------------
Version | connection details | diagnostics
```

## Workspace contracts

### Productions

`/admin/productions` is a production-card home, not a technical dashboard. It
lists title, channel, status, schedule, configuration, rundown/cue count,
active session state and the clearest next action. A first-run empty state
explains what a production contains and offers one primary create action.

### Prepare

`/admin/productions/:productionId/prepare` is an editor with secondary
navigation:

```text
Overview | Rundown | Viewer | Show configuration
```

- Overview: production details and non-blocking readiness guidance.
- Rundown: three columns on wide screens—cue list, typed selected-cue editor,
  real rehearsal Player preview.
- Viewer: bounded audience context and responsive profile preview.
- Show configuration: reusable defaults with an explicit copy-into-production
  lifecycle.

Prepare has one dominant action per sub-workspace: save. It may edit but never
silently alters an active immutable session.

### Rehearse

`/admin/productions/:productionId/rehearse` has amber, text-labelled
**REHEARSAL OUTPUT ONLY** treatment. It shows real Player preview, profile
selection, previous/current/next cue, a **GO IN REHEARSAL** action, reset, and
the isolated rehearsal session. Live outbox recovery controls do not appear.

### Run

`/admin/productions/:productionId/run` begins with a readiness gate. The live
workspace contains only programme preview, session/status context,
previous/current/next cue, large GO, navigation, dispatch recovery, deliberate
Safe Clear confirmation, and Complete show. It contains no configuration,
editing, or cue reordering.

An unresolved failed durable revision dominates the cue-control area and keeps
GO unavailable until retry or cancellation resolves ordering.

## Responsive and accessibility rules

- Desktop/tablet is the primary operating target.
- Narrow layouts stack Prepare as cue list, cue editor, then preview.
- Run retains GO, Safe Clear and critical status outside any navigation drawer.
- Status always includes text/icon as well as colour.
- Diagnostics are secondary, never part of the normal operating surface.

## Implementation sequence

1. Replace the current header/nav/context blocks with the stable shell.
2. Turn Productions into card/empty-state home.
3. Add Prepare secondary tabs and move existing sections into their correct
   sub-workspace without changing underlying APIs.
4. Build the Rundown three-column editor around existing typed cue operations.
5. Refocus Rehearse and Run using existing session/outbox safety logic.
6. Add diagnostics drawer/route and finish responsive/accessibility review.
