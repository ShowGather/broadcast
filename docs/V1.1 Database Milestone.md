# ShowGather V1.1 Database Milestone

## Scope

V1.1 makes ShowGather's product configuration and durable presentation state
persistent while retaining media PTS as the authority for timed/transient
presentation.

```text
Persisted production data
  -> durable command acceptance
  -> ordered outbox dispatch
  -> published snapshot
  -> timed media transport
  -> Player media-PTS scheduling and presentation rendering
```

## Delivered

- PostgreSQL and Prisma with a committed initial migration and idempotent demo
  seed data.
- Persistent organisations, channels, productions, rundowns, cues, snapshots,
  accepted command history, outbox state, and live/rehearsal rundown execution.
- Channel/production/rundown selection in the Admin, retained locally per
  operator browser.
- Operator-facing outbox status, event ID, reserved revision, failure reason,
  retry, and cancellation controls.
- Ordered retry using the original event ID and revision.
- Cancellation as a same-revision compact `noop` transport event: it advances
  the published revision without changing presentation state.
- Rundown execution that completes only after delivery, can retry failed live
  dispatches, and keeps rehearsal separate from live durable state.

## Validation evidence

Local Compose validation used PostgreSQL, API, stream injector, HLS, Admin, and
Player together.

1. A durable command was dispatched and survived API restart in the published
   snapshot.
2. Injector failure produced failed revision 3; revision 4 remained pending and
   the snapshot remained at revision 2.
3. Retrying revision 3 reused its original event ID and revision, then released
   revision 4. The snapshot advanced to revision 4.
4. A later failed revision 5 was cancelled. The no-op resolution left the score
   unchanged, while revision 6 dispatched and the snapshot advanced to revision
   6.

## Known limitations

- The V1 dispatcher assumes one active API dispatcher process per database.
  Multi-instance production deployment needs row claiming/leases, likely using
  `SELECT ... FOR UPDATE SKIP LOCKED`.
- PostgreSQL is local-pilot infrastructure only: no backup, HA, production
  secrets management, or remote deployment has been implemented.
- Admin supports focused selection and recovery, not broad production/rundown
  editing, organisation management, multi-user collaboration, or accounts.
- Browser timing was previously validated with Safari Technology Preview; this
  database milestone's live validation was API/Compose-level rather than a new
  browser timing measurement.
