# ShowGather V1.3 Renderer and UI Architecture

## Purpose

This document introduces a profile-aware presentation layer without making
timed transport responsible for layout.

```text
Presentation command      what changes
Presentation state        active instances and media-time lifetime
Profile resolver          destination, placement and variant
Component renderer        visual output
Viewer shell              video, surround and companion surfaces
Transport                 ID3/HLS or rehearsal SSE only
```

The existing delivery and recovery path remains unchanged:

```text
canonical command -> ordered outbox -> timed transport
  -> media-PTS scheduler -> presentation state -> renderer
```

## Current-state audit

Before this increment, every item was stored in a legacy logical region
(`video.overlay`, `header`, rails, or `footer`) and competed by a layer name.
That model already correctly provided priority takeover/restoration and
media-time expiry, but it made physical placement implicit. The Player also
used fixed CSS offsets for scorebugs, lower thirds and alerts.

The new layer preserves those legacy regions as command compatibility targets.
It does not rewrite stored snapshots, command envelopes, revisioning, outbox
delivery, rehearsal, or immutable sessions.

## Presentation instance model

Each activation can now carry an optional stable `instanceId`. If omitted, the
legacy layer name is used as its default ID, preserving current singleton
behaviour. Entries with distinct instance IDs can coexist in the same layer:

```text
layer: lower-third, instanceId: lower-third-presenter-a
layer: lower-third, instanceId: lower-third-presenter-b
```

Priority replacement is scoped to the same `layer + instanceId`; a temporary
sponsor takeover still restores the persistent sponsor after expiry.

The serialisable entry model supports optional `placementByProfile`,
`variantByProfile`, `zIndex`, and a bounded transition. These are durable
configuration/state fields, not timed-ID3 payload requirements.

## Placement and surfaces

The shared model defines:

- profiles: `desktop`, `tv`, `mobile`;
- surfaces: `video`, `surround`, `companion`;
- nine named anchors;
- normalised `x`, `y`, `width`, optional height/crop/opacity/rotation;
- layout policies: `single`, `row`, `column`, `overlay`;
- transitions: `cut`, `fade`, `slide`, `scale`.

Placement presets use title-safe normalised geometry. A preset is deliberately
not a pixel position: `bottom-left` on TV and mobile resolves to profile-safe
proportions. Invalid geometry is clamped before rendering.

## Legacy migration defaults

Existing commands continue to resolve without new payload fields:

| Item | Desktop | TV | Mobile |
| --- | --- | --- | --- |
| Scorebug | Video, top-left | Video, safe top-left | Compact video overlay |
| Lower third | Video, bottom-left | Video, safe bottom-left | Compact bottom-centre card |
| Sponsor | Existing surround region | Video, safe top-right | Partners companion surface |
| Ticker | Existing header/footer | Video, safe bottom-centre | Info companion surface |
| Alert | Video centre | Video centre | Compact video centre |

This prevents header/footer-originated content from silently disappearing on
TV or mobile while keeping current command mapping intact.

## Renderer rules

The Player resolves visible entries before profile routing, so temporary
priority takeovers cannot duplicate the underlying item. It then resolves an
intentional profile target. Video graphics use the real video container as a
CSS container and scale with bounded `cqw`/`clamp()` typography rather than
browser-width or fixed-pixel rules. Reduced-motion rules remain active.

No complete DVE configuration is sent in every timed event. Future timed
commands should reference or activate persisted instance configuration, keeping
the compact transport envelope bounded and backward-compatible.

## Acceptance-scene preview

The local Player exposes a deliberately transport-free renderer fixture for
the required shared scene:

```text
/player/:channelId?scene=acceptance&profile=desktop
/player/:channelId?scene=acceptance&profile=tv
/player/:channelId?scene=acceptance&profile=mobile
```

It contains Presenter A, Presenter B, the sponsor bug, scorebug and programme
clock as five instances with one set of content. The fixture bypasses snapshot
hydration so a local renderer demonstration cannot affect or be affected by
the live channel's durable presentation state.
