# ShowGather V1.1 Database and Recovery Release Candidate — v0.3.0-rc1

`v0.3.0-rc1` is a local-pilot release candidate for persistent production state
and reliable live-command recovery.

## Highlights

- Persistent demo organisation, channel, production, rundown, and cue data.
- Revisioned published presentation snapshots that survive API restart.
- Ordered transactional outbox for durable live presentation commands.
- Admin channel/production/rundown selection and live dispatch-status view.
- Safe retry with the original event ID and revision.
- Safe cancellation using a same-revision no-op transport event, avoiding
  revision gaps while leaving presentation state unchanged.
- Rundown completion tied to actual live dispatch; live and rehearsal execution
  state remain isolated.

## Setup

```bash
cp .env.example .env
pnpm install
pnpm pilot:up
```

Open the Admin at `http://localhost:3002` and follow the
[Pilot Demonstration Runbook](../Pilot%20Demonstration%20Runbook.md).

## Known limitations

- One active API dispatcher process per database is assumed.
- Local PostgreSQL/Compose is pilot infrastructure, not production hosting or
  high availability.
- No accounts, permissions, multi-operator collaboration, asset library,
  template editor, or general show editor.
- Timed ID3 remains a compact 127-byte TPE1 reference adapter.

## Verification

The release candidate passed the full workspace build/typecheck, Event Schema
(8), Presentation Model (3), API (8), Player (12), and Go TS-segmenter suites.
The local failure scenario verified ordered blocking, identity-preserving retry,
same-revision cancellation, and snapshot recovery across API restart.
