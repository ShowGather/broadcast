# ShowGather V1.1 Database and Recovery Release Candidate — v0.3.0-rc3

`v0.3.0-rc3` supersedes the unsuccessful CI candidates `v0.3.0-rc1` and
`v0.3.0-rc2`. It makes the repository CI-safe on a clean GitHub runner by
generating Prisma Client before API compilation and skipping local
PostgreSQL-only integration tests when `DATABASE_URL` is absent.

## Highlights

- Persistent channels, productions, rundowns, cues, snapshots, and command
  history backed by PostgreSQL.
- Ordered durable-command outbox with published snapshots only after delivery.
- Operator-visible pending, failed, retry, and cancellation recovery workflows.
- Same-revision no-op cancellation, preserving viewer revision ordering without
  applying the failed presentation change.
- Persistent live/rehearsal rundown execution state and API-restart recovery.

## Setup

```bash
cp .env.example .env
pnpm install
pnpm pilot:up
```

## Known limitations

- One active API dispatcher process per database is assumed.
- Local PostgreSQL/Compose is pilot infrastructure, not production hosting or
  high availability.
- No authentication, permissions, multi-operator collaboration, asset library,
  template editor, or broad show editor.
- Timed ID3 remains a compact 127-byte TPE1 reference adapter.
