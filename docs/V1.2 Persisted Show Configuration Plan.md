# ShowGather V1.2 — Persisted Show Configuration and Rundown Editing

## Outcome

An operator can create, configure, save, duplicate, reopen, and execute a
ShowGather production entirely through the Admin application, without editing
source code or depending on seeded runtime definitions.

```text
Create production -> configure defaults -> build rundown -> save
-> restart -> reopen -> execute live or rehearsal -> late viewer hydrates state
```

## Boundaries

V1.2 extends product configuration only. It does not change the canonical
command model, outbox, timed ID3/HLS path, rehearsal SSE path, Player media-PTS
scheduler, published snapshots, retry, cancellation, or revision semantics.

## Model

- `Production.configuration` stores a copied configuration snapshot.
- `ShowConfiguration` stores named reusable configuration presets per channel.
- A production can reference the configuration from which it was copied, but
  later preset edits never rewrite the production snapshot.
- `Rundown` and `RundownCue` remain the editable future-show definition.
- `RundownExecutionSession.rundownSnapshot` preserves cue ID, label, position,
  enabled state, command type, and canonical command payload at session start.

## Editing and execution rule

Starting live or rehearsal captures an immutable rundown snapshot. Subsequent
rundown edits affect future sessions only; an active show never changes under
an operator's feet.

## Duplication

Duplicating a production copies metadata, copied configuration, rundown
definitions, cues, ordering, enabled state, and canonical payloads into new
records. The new production starts as `draft`. It never copies sessions,
execution history, command logs, outbox records, snapshots, or live status.

## Non-goals

No authentication, roles, collaboration, drag-and-drop, assets, templates,
plugins, billing, analytics, production deployment, or general CRUD framework.
