# ShowGather V1.3 Acceptance Checklist

## Purpose

V1.3 validates one profile-aware presentation scene without changing the
proven delivery path:

```text
operator command -> durable/rehearsal delivery -> media PTS -> renderer
```

## Automated checks

Run before a release checkpoint:

```bash
pnpm --filter @showgather/presentation-model test
pnpm --filter @showgather/api test
pnpm --filter @showgather/player test
pnpm build
```

The presentation-model coverage includes instance identity, profile placement,
safe geometry, durable layout configuration, and deterministic row/column/
single collision policies. API coverage retains snapshots, revisions, outbox
retry/cancellation, and production configuration validation.

## Local stack check

```bash
docker compose --env-file .env -f deploy/compose/docker-compose.yml up --build -d
docker compose --env-file .env -f deploy/compose/docker-compose.yml ps
```

Confirm:

- API status reports both API and stream as connected.
- Admin opens on port 3002.
- Player opens on port 3003.
- HLS playlist is available from port 8000.

## Required shared scene

Create or open a production and define these independent instances:

| Instance | Desktop | TV | Mobile |
| --- | --- | --- | --- |
| Presenter A lower third | Video bottom-left | Safe bottom-left | Compact card/stack |
| Presenter B lower third | Video bottom-right | Safe bottom-right | Compact card/stack |
| Sponsor | Surround right rail | Safe top-right | Partners panel |
| Scorebug | Video top-left | Safe top-left | Compact video overlay |
| Programme clock | Video top-centre | Safe top-centre | Compact video overlay |

Use the Elements panel and named placement zones for selection, then save the
per-profile layout into the production. Verify that layout controls persist
after refreshing the Admin or restarting the API.

## Rehearsal and live run

1. Open the Rehearse workspace and use the real embedded Player.
2. Trigger the scene through rehearsal controls; confirm the opted-in preview
   changes and the live viewer does not.
3. Start a live session from Run only after the readiness screen is healthy.
4. Execute the same cues with GO.
5. Trigger Safe Clear and confirm video continues while presentation clears.
6. If a dispatch fails, verify that GO blocks until the revision is retried or
   cancelled through Diagnostics.

## Viewer resilience

For desktop, TV, and mobile profiles:

1. Open a late-joining viewer after persistent score/sponsor state has changed.
2. Confirm persistent state hydrates without replaying transient lower thirds.
3. Reconnect the viewer and confirm snapshot recovery remains ordered.
4. Pause and seek; transient items must use media time, not wall time.
5. Verify desktop surround regions, TV safe-area output, and mobile companion
   panels retain intentional destinations.

## Accessibility and motion

- Keyboard-navigate mobile companion tabs and Admin mode controls.
- Confirm labels and failure states use text as well as colour.
- Enable reduced motion and confirm transitions become minimal.
- Check focus is visible for placement zones, Safe Clear confirmation, and GO.

## Evidence to capture for the release candidate

- Admin Prepare/Rundown with Elements panel and placement zones.
- Rehearsal preview with its amber output-only treatment.
- Run workspace during a successful GO.
- Desktop, TV, and mobile versions of the shared scene.
- A late-join viewer showing persistent state.
- Any known limitation discovered during the run.

## Scope boundary

V1.3 deliberately does not add arbitrary HTML/CSS, freeform scripting,
asset uploads, authentication, collaboration, or production deployment
guarantees. Placement is bounded, profile-aware production configuration.
