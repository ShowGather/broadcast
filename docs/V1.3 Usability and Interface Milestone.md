# ShowGather V1.3 — Usability and Interface Milestone

## Outcome

V1.3 makes the persisted ShowGather production workflow practical for an
operator and clearer for an audience, without changing the proven timing,
outbox, snapshot, rehearsal, or session architecture.

```text
Prepare saved production
  -> rehearse with the real Player
  -> explicitly open a live session
  -> run the immutable session rundown
  -> timed presentation reaches video and surround regions
```

## Delivered

- Stable Admin routes for **Productions**, **Prepare**, **Rehearse**, and
  **Run**, retaining production context across refreshes.
- A focused Run console with an explicit live-session gate, current/next cue,
  navigation, GO/retry, independent Safe Clear, and outbox visibility.
- A live-session lifecycle with clear completion, abandonment, and reset
  confirmations. Run mode remains non-editing.
- Rehearsal previews that embed the real Player and offer desktop, mobile, and
  TV profiles without sending rehearsal output through the live ID3 path.
- Persisted audience context: programme title, subtitle, live label, accent,
  enabled companion panels, and editable companion tab labels.
- A viewer that collapses empty desktop rails, uses keyboard-accessible mobile
  companion tabs, keeps diagnostics opt-in, exposes connection problems to the
  audience, supports reduced motion, and gives TV graphics larger safe-area
  typography.

## Architecture preserved

No V1.3 change altered the following path:

```text
Canonical presentation command
  -> ordered durable outbox
  -> live ID3/HLS or rehearsal SSE
  -> Player media-PTS scheduler
  -> shared presentation model and renderer
```

Persistent state remains snapshot-backed. Temporary graphics remain governed
by media PTS and are never restored as durable snapshot content.

## Verification

On the local implementation commit, the following passed:

- full workspace production build;
- full workspace type check;
- 8 event-schema tests;
- 3 presentation-model tests;
- 11 API persistence and recovery tests;
- 2 Admin routing tests;
- 12 Player presentation, revision, and media-timeline tests;
- packet-preserving MPEG-TS segmenter test (`go test ./...`).

The local Compose stack was rebuilt with the V1.3 Admin, Player, and API
images. It reported a healthy API and stream; the Admin production route,
embedded rehearsal Player route, and HLS playlist each returned HTTP 200.

## Known limitations

- Browser interaction was not re-recorded during this checkpoint; the local
  route and stack checks complement, rather than replace, the prior Safari
  timed-metadata validation.
- The Admin remains deliberately compact and is not yet split into smaller
  feature modules.
- There is no authentication, multi-operator collaboration, asset library,
  plugin system, analytics, or production deployment guarantee.
- The outbox still assumes one active dispatcher per database.

## Next decision

V1.3 is a suitable local release-candidate boundary. The next product
increment should be selected from real operator feedback: either broaden
production usability (templates/assets) or test richer audience interaction.
It should not reopen the timing and recovery foundations without a specific
pilot finding.
